从字节到内存：重新理解 Go String

2026 年 11 月 12 日
|

日常写 Go 时，字符串看似只是文本：用 len 获取长度，用 range 遍历，再根据需要转换成 []byte。但遇到中文切片、循环拼接或并发读写时，理解字符串保存的到底是什么，就能避免不少误判。

本文以 Go 语言规范为准。关于字符串布局、共享和编译器优化的描述，参考 Go 1.25.8、macOS arm64 的实现；这些细节可能随版本、架构和编译方式变化。

字符串保存字节，len 返回字节数

Go 的 string 是不可变的字节序列，并不保证其中的字节一定是合法的 UTF-8。直接写在 Go 源文件里的普通中文文本通常使用 UTF-8，但从网络或文件读取的数据需要根据实际协议判断。

s := "Go语言"

fmt.Println(len(s))                    // 8：字节数
fmt.Println(utf8.RuneCountInString(s)) // 4：按 UTF-8 解码后的 rune 数

Go 占 2 字节，语言 中每个汉字占 3 字节，因此 len(s) 为 8。rune 代表 Unicode 码点；一个用户看到的字符也可能由多个码点组成，rune 数不一定等于用户感知的字符数。

例如 "é" 和 "e\u0301" 可能显示相同，但它们的字节序列不同，所以直接用 == 比较的结果为 false。如果业务要求将这样的文本视为相同，需要根据需求进行 Unicode 规范化。

索引和切片按字节，range 按 UTF-8 解码

s := "Go语言"

fmt.Println(s[0])  // 71：字节 'G'
fmt.Println(s[:2]) // Go
fmt.Println(s[2:]) // 语言

for i, r := range s {
    fmt.Printf("%d %c\n", i, r)
}
// 0 G
// 1 o
// 2 语
// 5 言

s[i] 得到一个 byte；s[low:high] 的边界也是字节索引，左闭右开。range 则依次进行 UTF-8 解码，返回当前码点的起始字节位置和 rune。

按字节切片可能切开一个 UTF-8 编码：

s := "A中B"
whole := s[1:4] // 中
part := s[1:2]  // 仅包含“中”的第一个字节

fmt.Println(utf8.ValidString(whole)) // true
fmt.Println(utf8.ValidString(part))  // false

字符串本身可以包含无效字节。range 遇到无效 UTF-8 编码时返回替换字符 U+FFFD 并前进一个字节；如果数据来自不可信输入，可以用 utf8.ValidString 检查。

字符串值与底层数据

在当前 Go 实现中，可以把一个 string 值理解为数据指针和字节长度；slice 则还包含容量。这个模型帮助分析共享，但布局不是业务代码应依赖的语言保证。

a := "Go语言"
b := a[2:]
底层字节：[G][o][ 语的 3 字节 ][ 言的 3 字节 ]
           ↑     ↑
           a     b

a 的长度：8 字节
b 的长度：6 字节

当前实现中，b 通常引用同一份底层数据，从字节偏移 2 开始；并没有因为切片操作而复制整段内容。赋值、传参也通常复制字符串描述信息，而不是复制所有字节。

如果只截取一小段却长期保存，引用可能让原来的一整块较大数据继续存活：

func prefix() string {
    content := strings.Repeat("a", 1024*1024)
    return strings.Clone(content[:10])
}

这里 Clone 为非空结果创建独立数据；如果再没有其他有效引用指向原数据，它就可以在后续 GC 中被回收。复制有成本，短暂使用的小片段通常不需要为了这个问题特意克隆。

不可变内容和变量赋值是两件事

a := "Go"
b := a

a = a + "语言"

fmt.Println(a) // Go语言
fmt.Println(b) // Go

字符串的字节不能通过普通 Go 代码修改，但变量 a 可以被赋予新的字符串值。b 的值不会因 a 被重新赋值而改变。

字符串的 == 比较字节内容，而不是比较底层地址：

a := "Go"
b := strings.Clone(a)

fmt.Println(a == b) // true：字节内容相同

因此，string 也适合用作 map key：不同地址的字符串只要内容相同，就能匹配同一个 key。读取不存在的 map key 会得到 value 类型的零值；需要区分“不存在”和“值恰好为零值”时，使用 value, ok := m[key]。

string 与 []byte 转换：先看行为，再看开销

s := "Go"
b := []byte(s)
b[0] = 'N'

fmt.Println(s)         // Go
fmt.Println(string(b)) // No

修改 b 不会改变原字符串；反过来，将 []byte 转为 string 后，再修改原切片也不会改变已经得到的字符串。这是程序可以观察到的行为。

为满足这种独立性，转换可能需要复制数据、准备新空间。复制不等于堆分配：副本也可能在栈上；编译器还可能在不改变可观察行为的前提下优化转换。

例如 Go 1.25.8 对符合条件的 m[string(bytes)] 临时 map 查询有避免复制的优化。我们在本机用 5 字节数据进行的小型基准中，这类查询观察到 0 allocs/op，而保存转换结果的例子观察到 1 allocs/op。这只描述特定测试，并非所有转换的保证；零堆分配本身也不足以证明没有发生复制。

拼接：避免在循环中反复复制已有内容

字符串不能原地修改。对于逐步构建结果的循环，反复使用 s = s + part 可能多次复制已经拼好的内容：

var b strings.Builder
for _, part := range parts {
    b.WriteString(part)
}
result := b.String()

Builder 内部使用字节切片：容量足够时向末尾写入；容量不足时可能分配新空间并复制已有内容。已知总字节数时，可以使用 Grow(n) 预留至少 n 字节的额外空间；不必为了避免扩容而预留远超实际需求的容量。

在 Go 1.25.8 中，Builder.String 引用已有缓冲区而不再次复制整段内容，这属于实现细节。已使用过的 Builder 不应按值复制，需要传递时可以传 *strings.Builder。

固定数量的简单拼接直接使用 + 即可；已有字符串切片并需要分隔符时，strings.Join(parts, sep) 通常更直接。具体性能取决于数据和上下文，值得优化时再做基准测试。

并发：内容不可变不代表变量可以并发读写

字符串完成初始化并被安全地提供给各 goroutine 后，如果没有任何写入，多个 goroutine 可以同时读取。

但如果一个 goroutine 读取变量，另一个同时给同一个变量重新赋值，并且两次访问之间没有同步，就可能发生数据竞争。它可能带来业务错误，也可能导致更严重的异常。需要共享更新时，使用锁、channel 等方式建立同步。

go test -race ./...

-race 是运行时竞态检测，只能检查实际执行到的路径；没有报告不等于代码绝对不存在竞争。完整的并发和内存模型留到单独专题。
